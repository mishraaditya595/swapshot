# MS-07 implementation plan: P0 playtest gate

Date: November 3, 2026. Base: merged MS-06 on `main`.

## Starting evidence

The owner's revised MS-06 browser recording shows a 02:25 win, all six troopers down, six successful SHIFTS and 4/100 armor left. Earlier browser recordings establish camera and rifle acceptance, but do not establish today's responsiveness, typical difficulty, post-victory browser replay, blocked SHIFT behavior, audio or frame rate. MS-06 Godot tests cover the core loop, reload, spawn selection and retry. Issue #15 requests multiple runs before changing armor recovery or Wave 2 damage.

## Approaches and decision

1. Change armor/damage immediately based on the single close win. Faster to implement, but an unmeasured balance change could flatten the firefight.
2. Preserve the recorded balance, close clear state/geometry risks, expand repeatable edge-case tests, and collect structured human playtest observations before deciding on tuning. **Chosen**, because MS-07 is the first dedicated playtest gate and the source evidence is too thin for numerical changes.
3. Build a new arena or AI system to force more varied fights. Rejected as P1 content work before P0 sign-off.

The user has explicitly requested implementation without a further approval round; this is a narrow verification and defect-correction pass within the approved P0 loop.

## Work

1. Trace input, rifle, safe SHIFT, enemy echo response, two-wave spawning and result/retry against the MS-01 through MS-06 regressions.
2. Prevent reinforcement entry points from overlapping the still-active SHIFT echo. Preserve safe delayed spawn selection if all candidate positions are temporarily blocked.
3. Add a standalone MS-07 headless physics suite for active-echo spawn avoidance, deliberately obstructed SHIFT landing/retry, exhausted spawn candidates and recovery, and repeated terminal replay. Wire it to CI.
4. Run the static audit, Python tests, Godot import/startup and MS-01 through MS-07 suites on the PR head. Record observed results rather than extrapolating.
5. Provide a short browser playtest script and observations table covering movement friction, camera/ADS, rifle cadence/cover, SHIFT usefulness, enemy threat clarity, Wave 2 pacing, victory/death replay, browser console, FPS and audio.
6. Review P0/P1 findings, preserve unknowns as unknowns, and publish a provisional Go/No-Go decision. Do not check the human playtest acceptance task or the milestone until there is human feedback on the actual MS-07 Web build.

## Proposed acceptance interpretation

Safe geometry, encounter state and regressions require new automated evidence. Combat fun, timing changes, HUD readability and host/browser behavior require hands-on evidence. A CI pass is necessary, but does not by itself authorize expansion to three zones. All P0/P1 findings must be resolved or explicitly marked as blockers.
