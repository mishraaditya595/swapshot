# MS-05 implementation plan

Branch: `feat/ms-05-security-trooper`. Scope: one guard and a short encounter, using the merged MS-04 ability.

## Architecture choice

The leanest implementation is a `StaticBody3D` guard with four explicit states. A `CharacterBody3D` guard with fixed strafing would add movement and collision tuning; a `NavigationAgent3D` implementation would add navigation data and asynchronous path behavior. Neither improves the first solo-developed firefight enough to justify the testing cost. The guard remains stationary for MS-05; cover-aware movement is deferred.

The guard owns detection, attack timing, its collider and `apply_damage`. Existing rifle hits use layer 1 without changing weapon masks. Detection and shots trace layers 1 and 2, excluding the guard's RID. SHIFT echoes remain collision-free, and the guard subscribes to the existing ability's echo lifecycle. The player's controller provides the small health receiver required to test real damage. MS-06 adds player health display, death and restart.

## Executable steps

1. Add `security_trooper.tscn` and the typed `security_trooper.gd`. Verify full-health rifle damage and permanent death.
2. Add four states with distance/FOV/geometry checks and yaw tracking; cancel windup on occlusion or target loss.
3. Add one telegraph and one cooldown; reraycast the muzzle-to-player path at discharge.
4. Connect `echo_spawned` and `echo_ended`, discarding freed echoes and disconnecting during teardown.
5. Build `ms05_firefight.tscn` from the unchanged training arena and make it the default preview.
6. Add physics-time smoke tests, register in CI, update README and tracker, review the diff, and request a browser playtest.

## Acceptance and rollback

The guard must detect, warn, shoot only through clear geometry, lose track behind cover, switch to the echo, reacquire the player, take rifle damage and never shoot after death. Keep MS-05 unchecked until runtime CI and owner gameplay acceptance are documented. Rollback is a single branch/PR; `greybox_arena.tscn` and previous tests stay unchanged.
